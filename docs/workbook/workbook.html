Appendix · 6502 instruction summary

Before you start

This workbook teaches 6502 assembly language on the KIM-1. Each part adds a few instructions or a piece of hardware, then gives you problems that use them. Early problems take three or four instructions. The last ones take a page. Try each problem before you turn to its answer at the back. There is usually more than one good solution, so an answer that differs from the book's can still be right.

Working in Kimulator

  • View › Assembler (Ctrl+E) opens the editor. F7 assembles, F8 loads the program into memory and makes its start the monitor's open cell, and F5 loads and runs it. The program starts at the start label.
  • View › Debugger (Ctrl+D) shows the registers and a memory editor. Use it to put test values into memory before a run and to check the results afterwards. You can also use the keypad: AD, an address, DA, a value, then + for the next cell.
  • Programs in Parts 1 and 2 end with BRK. With Machine › Preset NMI/IRQ vectors at power-on turned on (the default), BRK returns to the monitor. On a real KIM-1, store $00 at $17FE and $1C at $17FF first, so that BRK goes to the monitor.
  • Programs in Parts 3 and 4 run until you stop them with ST (Esc) or RS (F12).

Conventions

  • Programs start at $0200. Inputs and outputs are in zero page from $10 up, unless a problem says otherwise.
  • The KIM-1 has 1K of RAM, $0000–$03FF. Page 1 ($0100–$01FF) is the stack and the monitor uses $EF–$FF. That leaves zero page $00–$EE and $0200–$03FF for you, plus 64 bytes at $1780–$17BF.
  • “Byte” means 8 bits. 16-bit numbers are stored little-endian: low byte first. “($11:$10)” means the 16-bit number with its high byte at $11 and its low byte at $10.

Assembler syntax

Kimulator's assembler uses modern ca65/64tass-style syntax. It knows all the KIM-1 monitor's names (SCANDS, POINTL, SAD, …), so you don't have to define them.

        .org $0200          ; where the following code goes
COUNT   = 10                ; a constant
start:  ldx #COUNT          ; label, instruction, operand; # = immediate (the number itself)
@loop:  dex                 ; @local labels belong to the previous normal label
        bne @loop
        lda #<MSG           ; < low byte, > high byte of a 16-bit value
        lda #'A'            ; a character's ASCII code
        and #%00001111      ; $hex, %binary, plain decimal
        brk
MSG:    .byte "HI", $0D, 0  ; data: .byte, .word (16-bit, little-endian)
LEN     = * - MSG           ; * is the current address

Part 1 · First steps

The 6502 has three 8-bit registers you work with directly. A, the accumulator, does the arithmetic. X and Y are index registers, used for counting and stepping through tables. The program counter (PC) holds the address of the next instruction. The status register (P) holds flags that instructions set as a side effect. The ones you need first:

FlagSet when…
C carryan addition carries out of bit 7, or a subtraction does not need to borrow
Z zerothe result is zero
N negativebit 7 of the result is 1

An instruction's addressing mode tells the CPU where its operand is:

ModeExampleOperandBytes
ImmediateLDA #$42the number $42 itself2
Zero pageLDA $10the byte at $00102
AbsoluteLDA $0300the byte at $03003
ImpliedINX(built into the instruction)1

The most common beginner's mistake is to forget the #. LDA #$10 loads the number 16, but LDA $10 loads whatever is stored at address $0010.

The instructions in Part 1:

InstructionsWhat they do
LDA LDX LDYload a register from memory (or an immediate value); set Z and N
STA STX STYstore a register into memory; flags unchanged
TAX TAY TXA TYAcopy between A and X or Y
INX INY DEX DEYadd or subtract 1 in X or Y ($FF + 1 wraps to $00)
INC DECadd or subtract 1 in memory
CLC SECclear or set the carry
ADCA = A + operand + C. Clear the carry first for a plain addition
SBCA = A − operand − (1 − C). Set the carry first for a plain subtraction
BRKstop and return to the monitor

Carry as a chain. The 6502 only adds 8 bits at a time. To add bigger numbers, add the low bytes first, then the next bytes with the carry left by the step before, and so on. That is why there is no “add without carry” instruction: CLC at the start of the chain gives you one.

7Subtract two bytes

New: SECSBC

816-bit addition

Add the 16-bit numbers ($11:$10) and ($13:$12) and store the sum in ($15:$14).

$12FF + $0001 = $1300: put FF 12 01 00 at $10–$13 and expect 00 13 at $14–$15.

916-bit subtraction

Store ($11:$10) − ($13:$12) in ($15:$14).

$1300 − $0001 = $12FF; $0000 − $0001 = $FFFF.

10Times ten

The 6502 has no multiply instruction. N (0–25) is at $10. Store 10 × N at $11 using only additions. Aim for fewer than ten additions.

2N is N + N. Keep a partial result in a spare memory location.

N = 25 → 250 ($FA).

11Increment a 24-bit number

Add 1 to the 24-bit number at $10 (low), $11, $12 (high). You haven't met any branch instructions yet, so the program has to run straight through.

ADC #0 adds nothing but the carry.

FF FF 12 → 00 00 13; FF FF FF → 00 00 00.

12Negate a 16-bit number

Store −($11:$10), in two's complement, in ($13:$12).

−x = 0 − x.

1 → $FFFF; 1000 ($03E8) → $FC18; $8000 → $8000 (why?).

Part 2 · Decisions, loops and data

Comparing and branching

CMP, CPX and CPY subtract memory from a register without storing the result. They only set the flags. A branch then jumps if a flag is in a given state. Branches reach about 127 bytes forwards or backwards. For anything farther, use JMP.

After CMP value, if A is…thenso branch with
equal to valueZ = 1BEQ (BNE if not)
greater than or equal (unsigned)C = 1BCS
less than (unsigned)C = 0BCC
Branchif
BEQ BNEZ = 1 / 0
BCS BCCC = 1 / 0
BMI BPLN = 1 / 0
BVS BVCV = 1 / 0

Loads, transfers, INX/DEX, logic and arithmetic all set Z and N, so a loop that counts down to zero doesn't need a compare: DEX followed by BNE repeats until X reaches 0.

Indexed and indirect addressing

Absolute,X / ,YLDA $0300,X$0300 + X

Indirect indexedLDA ($10),Y(the 16-bit address stored at $10/$11) + Y

(zp),Y is the 6502's pointer. Keep a 16-bit address in two zero-page bytes, and you can reach any byte in memory. X and Y only go up to 255, so for bigger blocks, step the high byte of the pointer one page at a time.

Logic and shifts

InstructionEffectTypical use

EORA = A exclusive-or operandflip bits
BITZ = (A and operand) = 0; N = bit 7 and V = bit 6 of the operandtest bits without changing A

ROL / RORrotate left / right through C: the old C comes inmulti-byte shifts

Shifts and rotates work on A (ASL A) or directly on memory (ASL $10).

The stack and subroutines

JSR label pushes the return address on the stack (page 1) and jumps, and RTS returns. PHA/PLA push and pull A, and PHP/PLP do the same for the flags. Every push needs a matching pull before the RTS. Otherwise the subroutine returns to the wrong place.

Decimal mode

After SED, ADC and SBC treat each byte as two decimal digits (BCD): $19 + $01 = $20, and the carry means “over 99”. CLD switches back. The KIM-1 display shows hex digits, so a BCD number shows up in decimal on the display.

16Smallest and largest

17Masks

New: ANDORAEORBITBVCBVS

From the byte at $10, work out:

  • $11 = its low four bits (low nibble),
  • $12 = the byte with bits 7 and 0 set,
  • $13 = the byte with every bit inverted,
  • $14 = 1 if bit 6 is set, otherwise 0.

$5A → $0A, $DB, $A5, $01.

18Count the ones

New: LSR

Store the number of 1 bits in the byte at $10 in $11, leaving $10 unchanged. Can your loop stop as soon as there are no 1 bits left?

$5A → 4; $FF → 8; $00 → 0.

19Multiply

New: ASLROL

Multiply the unsigned bytes at $10 and $11 and store the 16-bit product in ($13:$12).

Do it the way you multiply on paper, but in binary. For each 1 bit in the multiplier, add the multiplicand, shifted left by that bit's position. A 16-bit value doubles with ASL on the low byte followed by ROL on the high byte.

200 × 3 = 600 ($0258); 255 × 255 = $FE01.

20Byte to hex text

New: JSRRTSPHAPLA

Convert the byte at $10 to two ASCII characters: the high hex digit at $11, the low one at $12. Write a subroutine NIBBLE that turns a value 0–15 in A into its ASCII digit, and call it twice.

ASCII '0'–'9' are $30–$39; 'A'–'F' are $41–$46.

$3C → $33, $43 (“3C”).

21Block copy

New: CPY and indirect indexed addressing, (zp),Y

Copy a block of bytes. The source address is at $10/$11, the destination address at $12/$13 and the count (1–255) at $14. The two blocks don't overlap.

copy 16 bytes from $0300 to $0380: 00 03 80 03 10 at $10.

What goes wrong if the blocks overlap and the destination is above the source? How would you fix it?

22SHOUT

$10/$11 points to a string of ASCII characters ended by a zero byte. Change its lowercase letters to uppercase in place, and store the string's length in $12.

Look at 'a' ($61) and 'A' ($41) in binary.

“Hello, KIM-1!” → “HELLO, KIM-1!”, length 13. Put the string in with .byte "Hello, KIM-1!", 0.

23Decimal addition

New: SEDCLD

$10/$11 and $12/$13 each hold a 4-digit BCD number, low byte first, so 1234 is stored as 34 12. Store their sum in $14/$15 and the carry (the ten-thousands digit) in $16.

5678 + 6789 = 12467: 67 24 and 01.

24Binary to decimal

Convert the byte at $10 (0–255) to decimal: the hundreds digit at $11 and the tens and units as packed BCD at $12. You will need this to show numbers on the display in decimal.

Take the bits from the top down. For each one, result = 2 × result + bit. If you do the doubling with ADC in decimal mode, the result is already BCD.

255 → 02, 55; 99 → 00, 99; 100 → 01, 00.

25Sort

$0300 holds a count N (2–255), followed by N unsigned bytes. Sort them into ascending order, in place.

Bubble sort. Compare each neighbouring pair and swap them if they're in the wrong order. Repeat until a whole pass makes no swaps.

05 05 03 09 01 03 → 05 01 03 03 05 09.

After each pass, the largest remaining value has reached its final place. Use that to make every pass shorter than the one before.

Part 3 · The KIM-1: display, keypad, timers and sound

Now for the KIM-1 itself. Its two 6530 RRIOT chips each hold 1K of ROM, 64 bytes of RAM, two 8-bit I/O ports and an interval timer. The 6530-002 runs the keypad, the display, the teletype and the tape. The 6530-003's ports go to the application connector and are yours to use.

Monitor routines

RoutineAddressWhat it does

The interval timer. Write a count N to one of the “start timer” addresses. The timer counts down once every 1, 8, 64 or 1024 clock cycles (µs on a 1 MHz KIM-1). Bit 7 of offset +7 goes to 1 when it has counted N + 1 steps, so for exactly T steps, write T − 1. Writing a new count starts the timer again and clears the flag. Reading offset +7 doesn't clear it. After the time-out, the counter keeps going down at the full clock rate, so the program has to restart the timer itself.

The display

Each digit's segments a–g are wired to PA0–PA6 of the 6530-002 (SAD). A 1 lights a segment once PADD = $7F. PB1–PB4 (SBD, with PBDD = $1E) feed a 74145 decoder whose outputs 4–9 select digits 1–6, so write (n + 4) × 2 to SBD to select digit n, counting 0–5 from the left. Only one digit is lit at a time. Show each one for about half a millisecond and go round again, and your eye sees them all at once.

Interrupts

An IRQ makes the 6502 finish its current instruction, push PC and P on the stack, set the I flag (so it isn't interrupted again straight away) and jump through the vector at $FFFE. On the KIM-1 that vector is in the monitor ROM, which jumps on through IRQV at $17FE/$17FF, so the handler's address goes there. The handler saves any register it uses, deals with the cause (for the timer, it writes a new count, which also clears the interrupt), restores the registers and ends with RTI. RTI restores P and PC. SEI and CLI turn interrupts off and on. BRK uses the same vector.

The 6530-003 timer's interrupt comes out on its PB7 pin. On a real KIM-1 you wire PB7 to the IRQ line yourself. In Kimulator, turn on Machine › Timer IRQ jumper.

Sound

The KIM-1 has no speaker. People connected an amplifier to a port pin and switched it on and off fast enough to be heard. A square wave of frequency f flips the pin every 1/(2f) seconds. In Kimulator, pick Machine › Sound › Application port PA0 to hear PA0 of the 6530-003.

32Egg timer

Count down from a time in minutes and seconds, kept as two BCD bytes MINS and SECS in the program. Show MMSS 00, and at zero stop and show 0000 EE. Keep time in quarter seconds by polling the 6530-003 timer between calls to SCANDS.

When the seconds go below zero in BCD, they should become 59 and the minutes should go down by one.

Restart the timer at the end of the loop instead of as soon as the flag is set, and time a minute. Why is it slower?

35Play a tune

Play a tune from a table of (pitch, length) byte pairs. The pitch is the half period in ÷8 timer steps, with 0 for a rest. The length is in 1/16 s units, and 0 ends the tune. Part 4 · The K-1008 Visible Memory

MTU's K-1008 Visible Memory is 8K of RAM that is also a picture: 320 × 200 dots on a monitor. The CPU uses it like any other memory, and the video circuit reads it between the CPU's accesses, so drawing never slows the program down. In Kimulator it is installed under Machine › Expansion cards…, at $2000 by default. View › Visible Memory display (Ctrl+G) shows the screen.

Screen layout
Size320 × 200 dots, 1 bit each
Line y40 bytes from $2000 + 40 × y
Shown$2000–$3F3F (8000 bytes)
Not shown$3F40–$3FFF (192 bytes)
In a bytebit 7 is the leftmost dot; 1 = lit

The dot at (x, y), with (0, 0) the top-left corner, is in

byte = $2000 + 40 × y + x ÷ 8    bit mask = $80 >> (x mod 8)

x goes up to 319, so it needs 9 bits: keep it as a 16-bit number. 40 × y reaches 7960, which is 16 bits too. The 6502 multiplies by 40 with shifts and adds: 40y = 8 × (4y + y).

Set a dot with ORA, clear it with AND of the inverted mask, and flip it with EOR. Flipping twice restores what was there, which makes EOR the classic way to move something across a picture.

37Paint the screen

Fill all 8K of the Visible Memory, $2000–$3FFF, with the byte at $10.

$00 clears the screen, $FF makes it white and $AA draws thin vertical stripes. What does $F0 draw?

Fill whole 256-byte pages with (zp),Y and step the pointer's high byte.

38Checkerboard

Cover the screen with 8 × 8 dot squares, alternately black and white, black in the top-left corner.

Work line by line with a pointer to the start of the line, adding 40 each time. Whether byte c of line y is white depends on c and y ÷ 8.

39Plot a dot

Write PLOT, which lights the dot at (XC, YC). XC is a 16-bit value (0–319) at $30/$31 and YC (0–199) is at $32. Use it to draw a frame around the edge of the screen and a diagonal from (0, 0) to (199, 199).

A table of the eight bit masks, $80, $40, …, $01, indexed by x mod 8, is quicker than shifting.

40Draw a line

Write LINE, which draws a straight line from (X0, Y0) to (X1, Y1), both ends included, in any direction. X0 and X1 are 16 bits and Y0 and Y1 are 8 bits. Draw a star of lines through the middle of the screen to test it. Bresenham's algorithm needs only additions:

dx = |x1 − x0|,   sx = +1 if x0 < x1, else −1
dy = −|y1 − y0|,  sy = +1 if y0 < y1, else −1
err = dx + dy
loop:  plot (x0, y0)
       if x0 = x1 and y0 = y1: done
       e2 = 2 × err
       if e2 ≥ dy: err = err + dy;  x0 = x0 + sx
       if e2 ≤ dx: err = err + dx;  y0 = y0 + sy

All these values fit easily in 16 signed bits. To test e2 ≥ dy, subtract dy from e2 and look at bit 7 of the result's high byte.

41Hello, world

Treat the screen as 40 columns × 25 rows of 8 × 8 dot character cells. Write PUTCH, which draws the character in A in cell (COL, ROW) and moves COL on by one. Write PRINT, which draws a zero-terminated string with PUTCH. Print “HELLO, WORLD!” in the middle of the screen and “KIM-1 6502” below it.

Cell (COL, ROW) starts at byte $2000 + 320 × ROW + COL, and its eight lines are 40 bytes apart. A full ASCII font doesn't fit in the KIM's RAM, so draw glyphs for just the characters you need, 5 × 7 dots in each 8 × 8 cell.

42Scroll up

Move the whole picture up by one character row (8 dot lines), the way a terminal scrolls, and clear the bottom row.

Count the bytes to move: it comes out to a whole number of pages. Does the order you copy in matter?

43Bouncing ball

Move an 8 × 8 ball around the screen, 2 dots at a time and 50 times a second, bouncing off all four edges. Draw it with EOR, so drawing it again in the same place erases it.

At position x, each 8-dot row of the ball's shape is shifted right by x mod 8 and spread over two bytes. Shift a 16-bit value, shape row : 0, right with LSR/ROR.

44Sketch pad

A pen starts in the middle of a clear screen and leaves a trail of dots. While a key is held, the pen moves one dot every 1/50 s: 9 up, 1 down, 4 left and 6 right. 0 clears the screen. The pen stops at the edges.

Add a pen-up/pen-down key, or diagonal moves on 8, A, 0 and 2.

Answers

These are the programs from docs/workbook/answers, without their header comments. Where an answer reuses a routine from an earlier one, the routine isn't printed again. The source file has it in full.

1Hello, memory

LDA #$42 loads the number itself. STA $10 is a zero-page store: 2 bytes, 3 cycles.

2Copy cat

A store doesn't change the register, so one load serves all three stores.

3Swap

With two registers there's somewhere to keep both values at once, so no temporary memory is needed.

4Neighbours

Increments and decrements wrap around: N = $FF gives $00 and $FE, and N = $00 gives $01 and $FF.

5Change it in place

INC and DEC read, change and write memory in one instruction, without touching a register.

6Add two bytes

ADC always adds the carry. Whatever ran before your program, the monitor included, may have left it set, and then the sum would be one too big.

7Subtract two bytes

For SBC the carry works the other way round: C = 1 means “nothing borrowed”. SEC first.

816-bit addition

One CLC at the start of the chain. The high bytes then add the carry left by the low bytes.

916-bit subtraction

The same chain with SEC/SBC. A borrow out of the low byte clears the carry, which takes one more off the high byte.

10Times ten

Five additions. With the shifts from Part 2 there is a shorter way: 10N = 2 × (4N + N) is three ASLs and one addition.

11Increment a 24-bit number

The same carry chain as problem 8. ADC #0 adds only the carry, which is 1 exactly when the byte below wrapped from $FF to $00.

12Negate a 16-bit number

0 − x as a 16-bit subtraction. $8000 (−32768) has no positive partner in 16 bits, so it comes out as itself.

13The bigger of two

After CMP, C = 1 means A ≥ the operand. Only when that fails does the program load the other value.

14Counting tables

The first loop stops when CPX finds X = $40. The second counts X down from $3F and stops when DEX wraps 0 to $FF, the first value with bit 7 set, so BPL falls through.

15Sum a table

An 8-bit addition into the low byte, and an INC of the high byte whenever it carries.

16Smallest and largest

Starting from the first element avoids having to choose “infinitely large” and “infinitely small” start values.

17Masks

AND clears, ORA sets and EOR flips the bits that are 1 in the mask. BIT copies bit 6 of memory into V without changing A.

18Count the ones

LSR moves bit 0 into the carry and sets Z when nothing is left in A, so the loop never runs more times than it needs to. INX changes Z, which is why A is tested again after it.

19Multiply

The multiplier is shifted right to look at one bit at a time, and the multiplicand is doubled for the next bit position. The loop stops when no 1 bits are left in the multiplier.

20Byte to hex text

PHA/PLA keep the byte while the high digit is converted. In NIBBLE, the carry left by CMP #10 is part of the arithmetic: for 10–15 it is set, so ADC #6 adds 7.

21Block copy

Both pointers use the same Y. If the destination overlaps the source from above, copying upwards overwrites bytes before they're copied. Copy from the top down instead, as memmove does.

22SHOUT

Lowercase and uppercase ASCII letters differ only in bit 5, but only letters may be changed, hence the range check. When the loop ends, Y has counted the characters.

23Decimal addition

Exactly problem 8 in decimal mode. CLD as soon as the BCD work is done: anything that runs later in decimal mode, a monitor routine included, gets wrong results.

24Binary to decimal

ASL takes the next bit into the carry. ADC of a value to itself then gives 2 × value + bit, and in decimal mode that stays BCD. The carry out of the tens is added into the hundreds.

25Sort

For the “going further” version, keep the number of pairs to compare in memory and reduce it by one after each pass. The worst case, a reversed list, needs N − 1 passes.

26Say something

SCANDS lights each digit once and returns. The display only looks steady because the loop calls it again straight away.

27Calculator entry

The 24-bit shift moves the digits left. Four shifts clear the low digit, and the new key is ORA'd in. A real keypad also bounces for a few milliseconds, but the 4 ms that SCANDS takes covers that.

28Tally counter

A BCD count shows in decimal on the hex display. CLD before returning to SCANDS.

29HELLO

This is what SCANDS does inside: select a digit, drive its segments, wait, move on. ASL of a number below 128 leaves the carry clear, so the ADC #8 needs no CLC.

30Marquee

The timer runs by itself while the program scans the digits, and one BIT per pass is enough to notice when it runs out. Y wraps at the end of the message, so it scrolls round forever.

31Read the keypad yourself

EOR #$FF turns “pulled low” into a 1, so any nonzero value means a key is down. The shifts then find the column, adding one to the code for each column passed.

32Egg timer

SCANDS takes about 4 ms, so the flag can be up to 4 ms old when the program sees it. Restarting the timer right away limits that to a small error per quarter second. If the restart comes later in the loop, every delay adds up: that is why the “going further” version runs slow.

33Interrupt-driven stopwatch

The interrupt happens within a few microseconds of the time-out, however busy the main loop is. The handler can safely use decimal mode: the interrupt saved P, with the main program's D flag, and RTI restores it. 155 + 1 steps of 64 µs is 9.984 ms. Add the handler's start-up time, and the watch is within about 0.1 %.

34Concert A

1/880 s is 1136 µs, 142 steps of the ÷8 timer. Take one off because the flag rises after N + 1 steps, and two more for the time the loop takes to notice the flag and restart.

35Play a tune

One loop watches both timers: the pitch timer flips the pin, and the length timer counts sixteenths. This loop takes longer to go round than problem 34's, so the pitch values are a little smaller.

36Keypad organ

The timer is started and the pin flipped before GETKEY runs, so reading the keypad doesn't change the pitch. Even D6's half period (0.43 ms) is longer than GETKEY takes. GETKEY relies on PADD = 0, so the program sets it, because no SCANDS runs here.

37Paint the screen

32 pages of 256 bytes. $F0 gives vertical stripes 4 dots wide.

38Checkerboard

Looking the byte up in a two-entry table avoids a branch. The line pointer steps by 40 with a 16-bit addition.

39Plot a dot

40 × y is computed as ((4y + y) × 8). x ÷ 8 shifts bit 8 of x into the result with ROR. The mask table turns x mod 8 into the dot's bit.

40Draw a line

sx is kept as a 16-bit $0001 or $FFFF, so stepping x is an ordinary 16-bit addition. Each comparison is a subtraction whose result is thrown away, all but the sign of its high byte.

41Hello, world

PUTCH finds the character in CHARS, and its position there × 8 is where its glyph starts in FONT. The glyphs use bits 6–2 of each byte, which leaves a column of space on each side.

42Scroll up

7680 bytes is exactly 30 pages. Copying upwards is safe because the destination is below the source. Each byte is read before anything is written over it.

43Bouncing ball

The ball is erased by drawing it again, then moved and drawn once more, all right after the frame timer runs out, so it's never missing from the picture for long. The bounces are exact because every position is even.

44Sketch pad

Problem 36's timing idea again. The frame timer starts before GETKEY and the movement, so the pen moves at a steady rate whatever the loop does.
